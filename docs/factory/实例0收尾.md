# 实例 0 收尾：三条 dev 分支怎么变成能评审的 PR

> 落盘 2026-10-31。所有数字都是可复算命令的输出，命令附在每条后面。

## 一、一句话现状

三条 dev 分支**没有一条是「垃圾分支」，也**没有一条能直接合**：
- 每条分支上**只有 1 条提交是真活**（另外 1 条是把当时工作区整个抄一遍的「基线」，内容后来已经由人工提交进了 master）；
- 真活之外还挂着 **1045 个 `.pnpm-store/` 文件 + 3 个 `.reasonix/` 文件**（共约 91 万行）；
- **三条分支一条都没推到远端**，所以一个 PR 都没有。

```
$ gh pr list --state all | wc -l
0
$ git ls-remote --heads origin | wc -l
1          # 只有 master
```

## 二、三条分支的真实成分

| 分支 | 自有提交 | 真活（排掉基线/gitignore/垃圾） | 垃圾 | 已推远端 |
|---|---|---|---|---|
| `agent/dev/cano-13` | 2 条 | `c420bc4` — 3 文件 +167/−7（引擎循环不再被渲染异常冻住） | 0 | 否 |
| `agent/dev/cano-14` | 2 条 | `2258423` — 2 文件 +235（HUD 遮挡的渲染测试） | **1045 pnpm-store + 3 reasonix** | 否 |
| `agent/dev/cano-15` | 2 条 | `d22f92b` — 13 文件 +848/−15（分享功能） | **1045 pnpm-store** | 否 |

复算：
```bash
git rev-list --count 2b6ee7f..agent/dev/cano-13        # 2
git show --shortstat --format='' c420bc4 -- . ':(exclude).pnpm-store' ':(exclude).reasonix' ':(exclude).gitignore'
git show --name-only --format='' 2258423 | grep -c '^\.pnpm-store/'    # 1045
```

### 基线提交不是垃圾，但它已经是孤儿

三条分支各有 1 条 `chore(agent): baseline — uncommitted work from the local directory`（`8aa3a48` / `4760b3a` / `7a1de0b`），各 9 个文件 680 行。查证结果：

```
$ git show e1ebd3c:README.md | shasum
3722ac16624c…
$ git show agent/dev/cano-13:README.md | shasum
3722ac16624c…        ← 完全相同
```
也就是说基线抄进去的那 9 个文件（README、`docs/multica/*`、`tools/multica/apply.mjs`），**人工在 11:20 已经提交进 master（`e1ebd3c`）了**，而且后面又被 `bd1e4bd`、`6740b57` 改过两轮。基线的价值只剩「证明当时工作区里有什么」，不需要合。

## 三、三条真活的实测结果（今天在临时工作树里跑过，没进主工作区）

| 分支 | 类型 | 单测 | 构建 | 结论 |
|---|---|---|---|---|
| cano-13 | exit=0 | **24 passed（3 文件）** | web 69.3KB / wx 11.5KB | **可以合** |
| cano-14 | exit=0 | **18 失败 / 44**（`games/arcade-dodge/src/__tests__/render.test.ts` 全红） | — | **不能合，是红测试** |
| cano-15 | exit=0 | **50 passed（6 文件）** | web 86.2KB / wx 13.9KB | **可以合** |

复算方式（一条一条来，不留痕在主工作区）：
```bash
git worktree add -q /tmp/wt agent/dev/cano-13
ln -s "$PWD/node_modules" /tmp/wt/node_modules
cd /tmp/wt && node_modules/.bin/vitest run && node_modules/.bin/tsc -p tsconfig.json --noEmit && node scripts/build.mjs
```

### cano-14 为什么红：它测的东西没人实现

它的测试 `import { hudLayout } from "../game.js"`，但 `hudLayout` 在 cano-14 自己的 `game.ts` 里**不存在**，在 master 里也不存在。也就是说这个开发写了一套「HUD 不重叠按钮」的断言，却没有写让它通过的实现。18 条红，全部是同一个原因。

这正好对上 CANO-14 这张票的验收标准第一条：「给出三种宽度下的实际坐标或截图，证明是否重叠」。测试写了，坐标没给，实现没做。

## 五、收尾工序（按顺序，每步都可回退）

### 第 0 步：先确认现在 master 上有什么
```bash
git log --oneline -1        # 0aac31f chore(repo): ignore .pnpm-store/ .reasonix/ .multica/
```
**注意**：我开工时 HEAD 是 `6740b57`，中途有人（20:52，作者 `wiiwings1988`）推了一笔 `0aac31f`，把 `.pnpm-store/`、`.reasonix/`、`.multica/` 加进了 `.gitignore` 并已推上远端。这笔提交是好的，但它**只挡住了将来的垃圾，分支里已经进历史的那 1045 个文件不会消失**。

### 第 1 步：把真活抽成干净提交（不碰基线、不碰垃圾）

实测过：`git cherry-pick -n` 会把整个提交连 `.pnpm-store` 一起带过来（cano-15 带进 1045 个文件）。所以必须在 no-commit 之后把垃圾剔掉：

```bash
git switch -c fix/cano-13-loop
git cherry-pick -n c420bc4
git reset -q -- .pnpm-store .reasonix .gitignore     # 剔垃圾（这几条本来也该由 0aac31f 负责）
git status --short                                    # 应只剩 3 个业务文件
```

三条各自要抽的提交：
- cano-13 → `c420bc4` → 落地后应只剩 3 个文件
- cano-15 → `d22f92b` → 落地后应只剩 13 个文件
- cano-14 → `2258423` → **先别抽**，它带 18 条红测试

### 第 2 步：cano-14 单独处置

三个选项，代价各不相同：

| 选项 | 做法 | 代价 |
|---|---|---|
| 补实现 | 在 cano-14 分支上补 `hudLayout`，让 18 条测试变绿 | 需要有人真去设计 HUD 布局，约半天；且票面警告「当前代码两处坐标互不相交」，可能白干 |
| 改成文档 | 把 `games/arcade-dodge/src/__tests__/render.test.ts` 里的坐标断言改成「产出实测坐标并贴进 issue」的脚本 | 半天；但直接回应了验收标准第一条 |
| 挂起 | 分支留着当证据，票标 `blocked`，注明「测试已写、实现未做」 | 零成本；但仓库里继续挂着 91 万行的分支 |

我的建议：**挂起**。理由是这张票连「到底重不重叠」都还没确认（客服核对说当前代码不重叠），先补实现等于给一个可能不存在的问题写代码。

### 第 3 步：推远端 → 开 PR → 过 CI

三条分支现在都没推到远端，这是「没有可评审 PR」的直接原因。

```bash
for b in fix/cano-13-loop fix/cano-15-share; do
  git push -u origin "$b"
  gh pr create --fill --base master --head "$b"
done
```
CI（`.github/workflows/ci.yml`）会自动跑：安装 → 类型 → 单测 → 构建。今天 master 上最近两次 CI 都是绿的（`gh run list --limit 2`）。

### 第 4 步：合 → 发版 → 回写票

合并后走 `node scripts/release.mjs --notes "…"` → `node scripts/publish.mjs --target local`，把版本号写回三张票（票面验收标准里都有「版本号写回」这条）。

## 六、这一步对「模板」意味着什么

丢掉这一节就白做了。这三条分支的形态，正是模板**默认值**的形态：

| 今天的默认值 | 派生出的新实例会继承什么 |
|---|---|
| agent 分支带 `.pnpm-store` 入历史 | 每条新产品线的每条 dev 分支都带 91 万行垃圾 |
| 分支不推远端、不开 PR | 每条产品线的「可评审 PR」都不存在，只有裸分支 |
| 票与分支的对应关系靠人记 | 收尾时要重新做一遍今天这个考证 |

**模板要改的默认值有两条，都不大：**
1. `.gitignore` 已经由 `0aac31f` 补上了（`pnpm-store` / `reasonix` / `multica`）——这条已经好了一半，缺的是**史上已经进过历史的垃圾怎么处理**（本次结论：不重写历史，抽真活重建分支即可）。
2. dev 岗位的合同里要加一句硬的：**任务结束时必须把分支推到远端并开 PR，否则不算交付**。现在 `docs/multica/agents/dev.md` 写的是「开 PR」，但没有写「不推远端等于没开」。
