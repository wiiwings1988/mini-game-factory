2. 手动触发 `feedback-triage`（run `01a18ff2-353d-7d22-b947-cc668c7f5a42`）。
3. 客服 agent 建出三条 issue 并写回反馈：

| 反馈 | 玩家原话 | 生成 issue | 状态 |

| `fb_ae219e6a` | 反馈按钮挡住最高分 | CANO-14 | todo |

4. 三个 issue 各起了一个 `开发-Dev` 任务（`01a18ff4-*`），在各自的 git worktree 分支上跑。

客服这一步的质量值得记一笔：它在 CANO-14 的正文里**主动核对了代码**，
指出「反馈按钮矩形在 `game.ts` 的 `feedbackButtonRect`、最高分画在左侧 `(14,40)`，
按 0.1.0 的坐标两者不重叠」，并要求开发按 320px / 390px 视口各测一遍再下结论。
这正是 `cs.md` 里写的「不许把玩家说改写成我们决定」。
